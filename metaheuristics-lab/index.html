How it works

Five ways to find a short tour

The travelling salesman problem asks for the shortest closed route that visits every city once. With n cities there are (n − 1)! / 2 possible tours, about 1080 for just 60 cities, so checking them all is impossible. These algorithms trade a guarantee of optimality for good answers, fast.

Constructive · baseline

Nearest neighbour

Start somewhere and always travel to the closest unvisited city. It's fast (O(n²)) but short-sighted: early greedy choices force long jumps at the end. Tours are typically 15–25% longer than optimal. Trying every start city and keeping the best helps a little.

tour ← [start]
while cities remain:
    go to the nearest unvisited city
return to start

Local search

Hill climbing (2-opt)

A 2-opt move removes two edges and reconnects the tour by reversing the segment between them, which untangles crossings. Each step tries every move and applies the best improvement. When nothing improves, it has reached a local optimum, so it restarts from a new random tour.

repeat:
    find the 2-opt move with the largest gain
    if no move improves: restart (or stop)
    else apply it

Trajectory metaheuristic

Simulated annealing

Like hill climbing, but it sometimes accepts a worse tour, with probability e−Δ/T. While the temperature T is high, it wanders and escapes local optima; as T cools geometrically (T ← αT), it settles into a good region. T₀ is calibrated so a typical uphill move is initially accepted 50% of the time.

T ← T₀
while T > T_min:
    repeat k times:
        try a random 2-opt move (gain Δ)
        accept if Δ < 0 or rand() < e^(−Δ/T)
    T ← α · T

Population · evolutionary

Genetic algorithm

Keeps a population of tours. Parents are picked by tournament selection. Order crossover (OX) copies a slice of one parent and fills the rest in the other parent's order, so children are always valid tours. Inversion mutation reverses a random segment, and elitism keeps the best tours. Without local search it converges slowly, which is why hybrid "memetic" variants exist.

population ← random tours
each generation:
    keep the elites
    while not full:
        child ← OX(select(), select())
        maybe invert a segment of child
    population ← children

Population · swarm intelligence

Bees algorithm

Inspired by honey-bee foraging. Scouts sample random tours (sites). The best m sites get recruited bees (more for the e elite sites), and each bee searches a "flower patch" of 2-opt moves around its site. Patches shrink when a site stops improving, and a site that stagnates too long is abandoned for a new scout, balancing exploration and exploitation.

sites ← n random tours
each cycle:
    for each of the best m sites:
        send nep (elite) or nsp bees
        move the site to the best neighbour
        shrink / abandon if stuck
    replace the rest with new scouts

Reading the results

A fair comparison

Each algorithm gets the same compute-time budget and its own seeded random generator, so runs are reproducible. The gap to leader shows how far each tour is from the best found in this race. That isn't necessarily the true optimum, except on the circle layout, where the optimal tour is the polygon itself.

Try the circle layout: 2-opt methods reach the optimum quickly. Then try 200 clustered cities and see which strategies scale.

About this project

Built from scratch, with no libraries

Metaheuristics Lab is a single-page app written in plain JavaScript modules, with no framework and no build step. The algorithms are pure modules, independent of the browser and covered by unit tests in Node.

  • O(1) move evaluation. A 2-opt move only changes two edges, so its gain is computed from four distances without rebuilding the tour.
  • Time-sliced runner. All algorithms run on the main thread; each animation frame gives every active algorithm an equal slice of CPU time, keeping the page responsive.
  • Reproducible. A seeded PRNG (mulberry32) drives map generation and every algorithm, and the map is encoded in the URL so you can share it.
  • Tested. The tests check tour validity, the 2-opt delta, budget enforcement, and that local search reaches the known optimum on convex instances.
